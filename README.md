# UNO CLUB

三个独立页面：`/` 经典 UNO、`/flip` UNO FLIP、`/flex` UNO FLEX。彩色牌全部带游戏开发部大头照，万能牌为 Kei。

## 线下四台设备一起玩

仓库保持 **Private**。GitHub 保存源码；联机房间由现场的一台电脑运行，朋友不需要 GitHub 账号。

1. 主机安装 Node.js 22.13 或更高版本，下载仓库后在目录中执行一次 `npm ci`（这一步需要网络）。
2. 四台设备连接同一个 Wi-Fi 或手机热点。在主机运行 `npm run deploy`（Node.js + SQLite，自动构建）。也保留 `npm run lan` / `start-lan.cmd` 的 Wrangler 本地运行方式。
3. 启动窗口会显示当前主机的局域网地址，例如 `http://192.168.2.47:3000`。四台设备打开窗口显示的地址；换网络后地址可能变化。
4. 房主选择“四台设备”，输入昵称创建房间，点击“邀请”。另外三人打开邀请链接并输入昵称入座，全部准备后由房主开局。
5. 主机保持开机、运行窗口开启。准备好依赖后，现场游玩不需要外网；图片、程序、房间数据库都在主机。

第一次启动会自动构建和创建本地数据库，重复启动不会清空牌局。停止用 `Ctrl+C`。默认端口 3000；脚本优先使用 Wi-Fi 网卡，并排除常见 VPN/虚拟网卡。多网卡可用 `UNO_HOST` 指定本机局域网 IPv4，`UNO_PORT` 指定端口。

若手机打不开，先确认使用的是局域网地址而非 `localhost`，设备没有连接隔离的访客 Wi-Fi。Windows 若弹出防火墙提示，请允许该服务访问你们使用的可信局域网；本项目不会自动关闭或修改防火墙。

## 房主切换设备模式

- 牌桌顶部的“四设备 / 单设备”由房主控制，其他设备只能查看当前模式。
- **四设备**：每位玩家使用自己的设备，只收到自己的手牌。
- **单设备**：房主设备轮流控制四名玩家，每次交接自动遮住手牌；其他已连接设备只看公共牌桌，不能出牌，也收不到手牌。
- 对局中切换保留手牌、牌堆、回合和分数，不重新洗牌。初始单设备牌局切成四设备后，另外三台设备可直接加入接管对应座位。
- 单设备是四人轮流操作，不包含 AI 对手。旧版本本机同屏存档仍可继续，新建单设备牌局统一使用本地房间服务，以支持随时切换设备。

## 使用

- 在线：输入昵称创建房间，把邀请链接给另外三位玩家。四人点准备，房主开局。房间保留24小时，同一浏览器刷新或重新打开原邀请链接可以重连；中途离场后，首页的“返回牌桌”也会恢复原座位与手牌。恢复需要原浏览器保存的记录，换浏览器或清除网站数据后无法仅凭昵称找回座位。
- 同屏：填写四个昵称；每次交接点击“我已接手”才显示当前玩家手牌。房间状态保存在运行服务的电脑上。
- 手牌先点击选中；鼠标再次点击选中牌，或触屏按住一张牌向上滑动至少 48 像素后松手出牌，也支持先点选再上划。设置中的“手机二次点击出牌”默认关闭；开启后再次点按选中的牌也可出牌。横滑仅浏览，不会出牌。万能牌随后选择颜色，强化定向牌另选目标。
- 手牌尺寸缩小至原来的 90%；悬停 / 横滑和选中均抬高 30 像素，包含不可出的牌。长手牌分组浏览，保留可点击的间距。可出的牌更亮，不可出的牌压暗；当前行动者的四角栏有明显边框。页面不滚动，规则与详情弹窗仍可内部滚动。
- 选中的卡牌显示实际效果和当前出牌条件；FLEX 开关只对带强化标记且能量可用的牌生效。普通牌仍按普通效果打出，能量翻转与全员恢复也会标注。
- FLIP 其他三位玩家的反面牌跟随四角座位显示；横屏在玩家栏的左右侧紧凑展示，并保留全部反面牌详情入口。“另一面”让自己的手牌原地翻转，卡牌位置和选中保持，方便对应明暗面；翻看时禁止操作，返回当前面后恢复出牌。官方说明书没有禁止查看自己另一面，本项目按允许查看的解释实现；单设备交接遮挡时隐藏手牌并退出翻看。
- 房间优先通过 WebSocket 实时同步，掉线后自动重连；连接失败时退回 HTTP 同步。玩家栏显示在线 / 离线。轮到掉线玩家时，房主可以等待重连或点“跳过离线玩家”；不会自动代打。有待结算罚牌时先由该玩家承担，再跳过。
- 点击顶栏“隐藏导航栏”释放牌桌空间，房间栏仍保留“显示导航栏”按钮，偏好会记住。
- 剩两张时可提前喊 UNO，提前声明只点亮 UNO 按钮；出到一张时提示一次，补喊则立即提示一次，重复点按不重复播放。功能牌先显示 UNO，再显示对应效果。漏喊可被举报。加牌叠加、相同牌抢出、500 分赛与排名赛在创建房间时选择。排名赛与 500 分赛互斥；排名赛前三位出完后结束，按出完顺序展示四人名次。每位出完者在玩家栏持续显示金色边框、VICTORY 与名次，其他设备收到提示；普通对局只对赢家显示 VICTORY，其他玩家显示 LOSE 和剩余手牌分数。
- 设置可关闭声音及震屏；系统“减少动态效果”默认关闭动画。“卡片高光”和“出牌人物卡片”默认关闭，后者控制卡面角色的登场动画，不影响玩家栏，保留已经明确保存的偏好。变色用颜色波纹呈现，不叠加文字。加牌、叠牌和禁人在目标玩家栏叠加光环、粒子与冲击图标；仅目标设备显示针对玩家的全屏效果，叠牌动画仍可全桌播放。牌桌背景未轮到你时变暗但保留颜色，轮到你时亮起；同时标明下一位行动者和实际顺 / 逆时针方向。

## 规则边界

依据 Mattel 经典 UNO、GDR44 FLIP 与 HMY99 FLEX 说明书实现，详细来源与规则在页面“游戏规则”中。

数字版约定：FLIP 每局随机生成双面配对，局内固定，非实体印刷配对复刻。FLEX 副色使用固定轮转分配。翻面后若新顶牌是万能，由下一位行动者选色。缺少可抽牌时只抽现有牌，避免无限循环。

可选叠加是房规，默认关闭。上一张数值加牌为 +N 时，允许接 +M，只需 M >= N（例如 +2 后可接 +4，+4 后不能接 +2）；N 是上一张牌的印刷数值，不是累计罚牌数，跨颜色与数值加牌种类可接。开启后数值万能加牌不检查手中是否有同色牌、不提供质疑；不叠定向 / 群体 / 抽色效果，FLIP 抽色牌保留其质疑规则。有人出完手牌时先结算最后一张罚牌，再计分或确认名次。

“相同牌抢出”也是可选房规：当前启用面的颜色、数字、功能和 FLEX 标记完全相同即可抢出，允许接自己刚打出的牌连出一对，回合从抢出者继续。刚摸牌或正在选色时不能抢出；有未结算罚牌时，只有同时开启叠加与抢出，且加牌来源为本人，才能继续抢出完全相同的数值加牌，累计罚牌仍交给原下一家。已经出完的玩家退出后续回合和效果目标。仅剩两位尚未出完的玩家时，Reverse（含 FLEX 普通与强化面）按 Skip 处理，跳过对手，由出牌者继续出牌。

## npm / Node.js 直接部署（无需 Wrangler）

```powershell
npm ci
npm run deploy
```

`deploy` 先执行 Next.js 生产构建，再以 Node.js + 内置 SQLite 启动。三种页面、四设备联机和单设备切换共用同一套规则与接口；不需要 Cloudflare 账号或运行时。也可拆开：

```powershell
npm run build:node
npm run start:node
```

- 默认监听当前局域网 IPv4 的 3000 端口，控制台显示邀请地址；可用 `UNO_HOST`、`UNO_PORT` 覆盖。服务器 / 容器可设置 `UNO_HOST=0.0.0.0`；域名反向代理可设置 `UNO_PUBLIC_ORIGIN=https://你的域名`，用于生成邀请链接。
- 房间存入 `.uno-data/rooms.sqlite`，可用 `UNO_DATA_DIR` 指定持久目录。重启保留未过期房间，房间有效期 24 小时。该目录已被 Git 忽略，请保留它及运行中的 SQLite WAL 文件。
- Node 与 Wrangler 使用独立的数据目录（`.uno-data` / `.wrangler/state`），不自动迁移正在进行的牌局；更换运行方式后新建房间即可。同一场对局的四台设备必须连接同一服务地址。
- 服务需要持续运行；GitHub Pages 是静态托管，不能单独承载房间接口。[Next.js 自托管说明](https://nextjs.org/docs/app/guides/self-hosting)、[Node SQLite 文档](https://nodejs.org/api/sqlite.html)。

## 本地开发

Node.js >=22.13，npm。依赖已经在当前交付目录安装。

```powershell
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_tiresome_punisher.sql
npm run dev -- --port 5173
```

数据库迁移只在新的本地数据库执行一次。不要在已存在的表上重复执行。开发服务默认为本机访问。手机预览用 `npm run dev -- --hostname 0.0.0.0`，然后在同一 Wi-Fi 中打开电脑的局域网地址（5173 端口）。

```powershell
node --experimental-strip-types tests/game.test.mjs
node tests/room.test.mjs
node tests/websocket.test.mjs
```

触屏与布局回归测试在 `tests/interaction.test.mjs`，需要 Playwright 和运行中的服务；可用 `UNO_PLAYWRIGHT_MODULE` 指定 Playwright 模块，用 `UNO_CHROME_PATH` 指定 Chromium 可执行文件。浏览器模拟触屏不能替代实机检查。

`tests/fonts.test.mjs` 用相同浏览器配置核验自托管字体与素材校验和，报告写入 qa-fonts.json。

`tests/table-effects.test.mjs` 核验目标冲击、排名提示、回合光照、方向与 UNO 队列顺序，报告见 qa-table-effects.json；`tests/flip-hand.test.mjs` 核验原地翻面、查看时禁止操作、横屏座位侧置反面牌，报告见 qa-flip-hand.json。

后一个测试需要本地服务已经运行。可通过 `UNO_TEST_URL` 指定地址；测试 Node 版本时设置 `UNO_TEST_RUNTIME=node`，报告写入 qa-network-node.json。四会话测试不代表真实跨地区网络延迟测量。

## 实现

- React / TypeScript；Node.js + SQLite 和 Vinext / Cloudflare Worker + D1 两种持久化运行方式。
- 服务端权威判定，版本比较更新避免同时操作覆盖；操作标识防止重复提交。
- 每个座位有随机凭证，服务器只存SHA-256摘要，客户端仅收到自己手牌。
- WebSocket 在鉴权后为每个座位单独生成完整视图，不广播包含操作人手牌的响应。Node 使用 ws；Cloudflare 使用每房间一个 Durable Object。心跳及连接关闭维护在线状态，在线状态变动不修改牌局版本。WebSocket 不通时启用 HTTP 退路；后台断开，返回页面立即重新同步。准备操作明确设置自己的准备状态，并发写入时重新读取、合并重试；出牌仍按版本检查，避免旧状态误出牌。不提供 AI 代打。
- 游戏核心在 lib/game.ts；在线接口 app/api/room/route.ts；页面 app/ui/arcade.tsx。
- 浏览器 WebMCP 提供只读牌桌工具，尊重同屏遮挡。

## GitHub 交付

仓库保存完整源码，访问权限为 Private。没有启用 GitHub Pages 或公开云部署。当前交付是可运行的同一局域网版本；GitHub 仓库链接本身不是游戏网址。房间需要服务端和数据库，纯静态 Pages 不能独立运行房间接口。

`npm run deploy` 使用 Node.js + SQLite；原 `npm run lan` 使用 [Cloudflare 本地运行时与 D1](https://developers.cloudflare.com/workers/local-development/local-data/)。两者都不需要 Cloudflare 账号或付费服务。
